שלום, אני שהד ריאן — בוגרת מדעי המחשב בחיפה, ובוגרת בוטקאמפ FURSA ב-AI וב-DevOps.

היום אציג את פרויקט הגמר שלי, Recall. ולא חיפשתי נושא לפרויקט — הייתה לי בעיה אמיתית בקורס, ורציתי משהו שיעזור לי כבר עכשיו.

Recall זה AI study tutor. נותנים לו חומר — PDF, טקסט או נושא — והוא הופך אותו ל-cards, בודק את התשובות שלי, ומחליט מתי אראה כל card שוב.

בבוטקאמפ למדנו נושא חדש כל שבוע — Python, AWS, Docker, Kubernetes, Terraform.

בהתחלה זכרתי, ועם הזמן הידע התחיל להיעלם.

זו עקומת השכחה — בלי חזרה, הזיכרון יורד משמעותית כבר אחרי יום.

ואז הבנתי: הבעיה לא הייתה ללמוד — אלא לזכור.

ואם עושים את זה ידנית עם flashcards — צריך לא רק ללמוד, אלא לנהל את כל התהליך: לכתוב שאלות, לבדוק תשובות, לתת לעצמנו ציון, ולהחליט מתי לחזור.

עם 200 cards זה כבר הופך לעבודה בפני עצמה — במקום ללמוד.

אז שאלתי: מה אם המערכת תעשה את כל זה בשבילי?

בואו נראה חי.

זו המערכת — רצה עכשיו על ה-Kubernetes cluster שלי, לא local.

שלושה חלקים בלבד: Add material — מביאים חומר. Study — לומדים. Progress — רואים איפה אני עומדת.

ובואו ניצור deck חדש מולכם. תזרקו לי נושא.

ובזמן שזה רץ — מה קורה מאחורה: ה-Agent קורא את החומר וכותב את השאלות בעצמו. הוא מנסה לייצר שאלות שבודקות אם הבנתי, לא שינון.

וזהו — ה-deck מוכן. השאלות האלה לא היו קיימות לפני דקה.

אני נכנסת אליו. שימו לב — כל ה-cards זמינים מיד, הם חדשים.

תראו את השאלה הזאת.

האדי — תענה לנו.

ותשימו לב שהוא צריך לשלוף מהראש. זה active recall.

והוא לא אומר "נכון" או "לא נכון". הוא נותן score, מראה את התשובה המלאה, ומסביר מה בדיוק פספסנו.

וכבר קבע מתי נראה את ה-card הזה שוב — התשובה הייתה חלקית, אז הוא חוזר מחר.

ועכשיו אחד נוסף — הפעם תשובה מלאה.

score גבוה — ותראו את התאריך. הוא לא מחר, הוא נדחף הרבה קדימה.

אותה מערכת, שתי תשובות — שני תאריכים שונים לגמרי.

ובמסך ה-Progress: ה-accuracy שלי, וגם — הכי שימושי — הנושאים שאני הכי נכשלת בהם.

כי לכל card יש state משלו ב-DynamoDB: כל תשובה, כל score, כל תאריך.

ורציתי מערכת אמיתית, לא רק demo. זה Grafana — כל ה-requests שעשינו עכשיו נמצאים כאן, live. וכאן error rate וה-health של ה-services.

ראינו את המערכת מבחוץ. עכשיו מה שקורה מאחורי הקלעים.

וכל יום אני מקבלת email שמזכיר לי כמה כרטיסים יש לי היום — כדי שלא אשכח לחזור.

והאלגוריתם שקובע את התאריכים הוא SM-2: טעיתי — מחר. צדקתי — 1, 6, 15, 39, 97 ימים.

זה Active Recall ו-Spaced Repetition.

אתם רואים את השכבות, אז במקום לעבור תיבה־תיבה — אקח סטודנט אחד ואראה מה קורה לו.

הוא נכנס לדפדפן, בוחר נושא, ומעלה PDF.

ה-PDF מגיע ל-Frontend, והמסמך הגולמי נשמר ב-S3 — שם יושבים כל החומרים המקוריים.

משם התוכן נשלח ל-Tutor Agent: הוא ממיר אותו לטקסט, ומעבד עם NLP כדי להבין מה כתוב — ומתוך זה מייצר חומר לימוד ושאלות.

וכאן הנקודה המעניינת: ה-Tutor Agent לא עושה הכל בעצמו. כשמשימה דורשת התמחות הוא שולח אותה ל-Sub-Agent המתאים, וה-Sub-Agent מחזיר לו את התוצאה.

כלומר יש כאן communication between agents — כל Agent עושה את מה שהוא מתמחה בו. וכשצריך לגעת במידע, זה עובר דרך MCP: הסוכן מחליט, ה-tool מבצע.

ובסוף ה-Tutor Agent מחזיר לסטודנט את החומר ואת ה-cards.

וזה כל המסלול: מהדפדפן, דרך S3, ל-Tutor Agent, ל-Sub-Agents — וחזרה לסטודנט.

Observability זה לדעת מה קורה למערכת בלי לבהות במסך.

Prometheus אוסף מדדים מה-agent, Alertmanager מחליט מתי להתריע, ו-SNS שולח מייל.

ה-agent מפסיק לענות — Pending. וכאן הלב: for 2m — מתריעים רק אם הבעיה נמשכת שתי דקות, כדי לא לקבל מייל על כל blip.

נמשך — Firing — מייל FIRING. חזר — RESOLVED, וה-alert נסגר לבד.

המערכת מנטרת את עצמה — ורק כשמשהו באמת נשבר, מייל מחכה לי.

והכל רץ כ-Docker containers על Kubernetes על EC2. את ה-cluster הקמתי בעצמי, את התשתית ב-Terraform, וה-deployment אוטומטי — כל push בונה image ו-Argo CD מסנכרן.

הכלל בבדיקות: מה שלא בשליטתי — mock. מה שכן שלי — בודקים באמת.

את AWS אני עושה mock — אין טעם שאני אבדוק את אמזון. אבל את SM-2 — הלוגיקה שקובעת מתי card חוזר — אני בודקת על כל מסלול ציון, כי אם היא טועה, כל הלמידה טועה.

בערך 235 unit tests, ומעליהם integration אמיתי: MCP server אמיתי מול DynamoDB Local, מסלול שלם — card נוצר, נשלף בזמן, ומתעדכן אחרי ציון.

וכל PR חייב להיות ירוק.

ה-AI כתב הרבה מהקוד — אבל לא קיבל אף החלטה.

עבדתי spec לפני קוד, ואז test first: הבדיקה מגדירה מה נכון, לא המודל.

ה-intervals של SM-2, וה-fail-safe כשהציון לא תקין — אלה היו שלי.

אז זה Recall. התחלתי מבעיה אישית — לומדת ושוכחת — ובניתי מערכת שעושה את זה בשבילי.

ובניתי אותה כמערכת אמיתית, עם deployment ו-monitoring — שגם אחרים יוכלו להשתמש בה.

תודה, אשמח לשאלות.
