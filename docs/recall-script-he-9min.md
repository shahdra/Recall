# 10 · Architecture — שקף 10 ⭐

**TIME:** 1:20 · *החלק הטכני המרכזי*

**WHAT I DO ON SCREEN:** **לא לקרוא את הדיאגרמה.** לעקוב עם היד: דפדפן → S3 → Tutor Agent → Sub-Agent → חזרה. **לעצור על החץ בין ה-Agents.**

**WHAT I SAY:**

> אתם רואים את השכבות, אז במקום לעבור תיבה־תיבה — **אקח סטודנט אחד ואראה מה קורה לו.**
>
> הוא נכנס לדפדפן, בוחר נושא, ומעלה **PDF**.
>
> ה-PDF מגיע ל-**Frontend**, ו**המסמך הגולמי נשמר ב-S3** — שם יושבים כל החומרים המקוריים.
>
> משם התוכן נשלח ל-**Tutor Agent**: הוא ממיר אותו ל**טקסט**, ומעבד עם **NLP** כדי **להבין** מה כתוב — ומתוך זה מייצר חומר לימוד ושאלות.
>
> **וכאן הנקודה המעניינת:** ה-Tutor Agent **לא עושה הכל בעצמו**. כשמשימה דורשת התמחות הוא **שולח אותה ל-Sub-Agent המתאים**, וה-Sub-Agent **מחזיר לו את התוצאה**.
>
> כלומר יש כאן **communication between agents** — כל Agent עושה את מה שהוא מתמחה בו. וכשצריך לגעת במידע, זה עובר דרך **MCP**: **הסוכן מחליט, ה-tool מבצע.**
>
> ובסוף ה-**Tutor Agent מחזיר לסטודנט** את החומר ואת ה-**cards**.
>
> וזה כל המסלול: **מהדפדפן, דרך S3, ל-Tutor Agent, ל-Sub-Agents — וחזרה לסטודנט.**

**TRANSITION:** **`↓` פעמיים** (מדלגת על שקף 11) → שקף 12.

# ❓ שאלות

- **למה Sub-Agents?** → התמחות, context קטן, תחזוקה נפרדת.
- **למה MCP?** → ה-Agent מקבל interface של tools, לא גישה ל-storage. הסוכן מחליט, ה-tool מבצע.
- **S3 מול DynamoDB?** → S3 לקבצים גולמיים, DynamoDB ל-structured data לפי key.
- **score לא תקין?** → fail-safe ל-"incorrect", ה-card חוזר מחר.
- **למה `for: 2m`?** → לא לקבל מייל על blip של שנייה.
